# 智扫通 Agent 企业级优化蓝图

> 本目录只保存分析与实施设计，不修改、不复制现有 Demo 的业务代码、知识库和配置。当前版本是规划基线，不是可运行的新系统。

## 1. 结论先行

现有项目已经完成了一个垂直领域 Agent 的关键技术闭环：Streamlit 对话入口、LangChain Agent、工具调用、中间件、Chroma 检索增强生成（RAG）以及使用报告场景切换。它适合作为功能验证 Demo，但距离可对客户稳定交付的企业级产品仍有明显差距。

当前成熟度可判断为 **PoC / Demo（约 30%）**，而不是生产 MVP。主要原因不是 Agent 主链路缺失，而是用户身份、真实数据、可靠性、安全、评测、运维和交付体系尚未建立。

### 当前已完成

- 可通过聊天界面发起问题并流式展示回答。
- 已接入通义聊天模型和向量模型。
- 已定义知识问答、天气、用户、月份、外部记录和报告上下文等工具。
- 已具备本地知识文件加载、切分、向量化、检索和总结链路。
- 已用中间件记录工具调用，并按上下文切换报告提示词。
- 已准备扫地机器人知识资料和模拟用户月度数据。

### 生产化缺口概览

| 维度 | 现状 | 用户影响 | 目标状态 | 优先级 |
|---|---|---|---|---|

## 2. 用户视角的产品目标

企业化不能只把代码拆成更多目录。建议先以四类用户定义成功标准：

1. **终端用户**：能快速得到可信答案；不知道怎么问时有引导；回答给出来源；失败时知道下一步；个人报告必须属于本人。
2. **客服/运营人员**：能看到低满意度会话、人工接管、纠错知识并验证效果，而不是只能查看开发日志。
3. **知识管理员**：能上传、校验、审批、发布、撤回和追踪知识版本，删除文档后索引同步删除。
4. **平台管理员**：能控制租户、账号、权限、模型配额、敏感操作与审计记录。

建议首个生产 MVP 聚焦三条旅程：

- **故障排查**：用户描述现象 → Agent 补问关键条件 → 检索可信步骤 → 给出逐步处理和安全边界 → 未解决时转人工。
- **知识咨询**：用户咨询选购/维护 → 给出简明结论和来源 → 支持追问 → 收集有用/无用反馈。
- **个人报告**：完成身份校验 → 选择月份 → 获取本人数据 → 生成结构化报告 → 支持导出或分享（是否实现需确认）。

生产 MVP 建议指标：首字响应时间、完整响应 P95、任务完成率、引用命中率、无依据回答率、报告数据一致率、转人工率、用户满意度、单次会话成本。

## 3. 关键技术差距

### 3.1 产品与前端

- 对话仅保存在 Streamlit Session，刷新或换设备后丢失。
- 重资源生命周期分散：聊天模型与向量模型是模块级单例（model/factory.py 导入即创建），向量库用 lru_cache(maxsize=1) 常驻进程且未显式关闭，而 Agent 按会话重建；缺少统一管理与优雅释放。
- 没有身份认证、会话列表、停止生成、重试、反馈、引用展示、文件入口和人工兜底。
- 会话历史只把最后一个 chunk 写入 st.session_state（reponse_messages[-1]），刷新或重跑后历史里的助手回答不完整。
- 当前代码未将历史消息传回 Agent，多轮界面看似存在，但模型实际上每次只收到本次输入。

### 3.2 Agent 与业务流程

- 报告流程依赖提示词要求模型按固定顺序调用工具，缺少代码层状态机、参数校验和幂等保障。
- 报告上下文是一次请求内的可变字典，没有稳定、可持久化的会话状态模型。
- 工具只有统一的 8 秒 HTTP 超时（HTTP_TIMEOUT_SECONDS），没有重试、熔断、限流、权限校验、错误码与降级契约。
- 工具入参缺少统一校验：只有部分工具做了空值/格式检查，异常直接抛出，模型只能凭错误文本自行纠正。
- 没有输入注入防护、输出安全策略、敏感数据脱敏和高风险操作确认。
- 提示词已要求不展示内部推理、只给简短进度说明；但工具调用与回答依据只落在本地日志，用户侧缺少可留存的依据摘要与引用。

### 3.3 数据与 RAG

- 知识索引依靠 MD5 文本文件判断新增，无法可靠处理更新、删除、失败回滚和并发导入。
- 文档元数据、版本、权限、租户隔离、来源 URL、发布日期和有效期没有标准模型。
- 检索只有向量 Top-K，没有关键词/混合检索、过滤、重排、查询改写和置信度门槛。
- 回答没有可展示引用，用户无法验证信息来源。
- 索引构建与在线查询共用应用工程，没有离线任务、状态追踪和失败重试。
- RAG 链会直接打印完整提示词和资料，可能将用户问题或知识内容泄露到控制台日志。

### 3.4 安全与隐私

- config/rag.yml 以明文保存可用的 API Key（已被 .gitignore 排除，仓库中只有 rag.yml.example 模板）；建议改为环境变量注入并轮换一次 Key。
- 用户 ID 由使用者手填、只与本地 CSV 做存在性校验：没有登录态与数据授权，任何人均可查询他人记录。
- 没有权限模型、租户隔离、审计日志、数据保留/删除策略、传输与存储加密约束。
- 本地日志可能记录工具参数、用户问题和返回内容，没有脱敏与访问控制。
- 已补上 .gitignore（排除密钥、日志、向量库与运行产物），仍需防范本地误提交与密钥轮换遗漏。

### 3.5 工程质量与交付

- README 已补齐安装、运行、配置、工具清单、设计要点与已知局限，仍缺少排障手册与架构图。
- 只有未锁版本的直接依赖清单 requirements.txt，缺少 lock 文件与依赖安全扫描，运行环境不可复现。
- 没有单元、集成、端到端测试，也没有离线 Agent/RAG 评测集。
- 没有 API 契约、数据库迁移、任务队列、缓存和服务健康检查。
- 没有容器、CI/CD、开发/测试/生产环境隔离、版本策略和回滚方案。
- 日志以进程本地文件保存，没有 request_id、conversation_id、tool_call_id、延迟、Token、成本和告警指标。
- Demo 已托管在 GitHub（robot-customer-service-agent），但没有分支策略、提交规范、CI 检查与发布流程。

## 4. 冲突与待确认决策

以下事项会改变现有行为或产品边界。**在你确认前，它们不进入默认实施基线，也不会修改原 Demo。** 建议先批准 C01、C02、C03、C04，再启动生产 MVP。

| 编号 | 冲突点 | 当前设计 | 建议 | 需要你确认什么 |
|---|---|---|---|---|
| C01 | 思考过程展示 | 提示词已要求不展示内部推理，只输出简短进度说明 | 保持现状，并把该口径写进产品规范 | 是否需要在用户侧保留可审计的依据摘要（当前依据只在本地日志） |
| C02 | 报告编排 | 由模型自行决定固定工具顺序 | 改为代码控制的确定性工作流，Agent 只负责理解与生成 | 是否接受降低该场景的 Agent 自主性 |
| C03 | 身份与授权 | 用户 ID 由使用者手填并与本地 CSV 校验；月份为真实系统月份；位置为真实 IP 定位（城市级） | 用户 ID 来自登录态并做数据授权，位置获取需用户知情 | 首期接入真实用户系统，还是保留 CSV 适配器 |

| C08 | 报告交付 | 仅聊天 Markdown | 可增加历史报告、导出和分享 | 首期是否需要 PDF/下载/分享 |

| C10 | 原数据迁移 | Demo 已有 Chroma/MD5 数据 | 新项目重新构建可追踪索引，默认不复制旧索引 | 是否需要迁移旧知识和历史数据 |

## 5. 目标架构

建议采用“模块化单体 + 异步任务”的第一阶段架构，先确保边界清晰、可测试、可部署，再根据实际负载拆微服务，避免为 Demo 过早引入分布式复杂度。

```text
正式 Web / 内部调试台
        |
API 网关：认证、限流、请求 ID、流式协议
        |
应用层：会话服务 / 问答用例 / 报告工作流 / 反馈服务
        |
领域层：Agent 编排 / 工具契约 / RAG / 安全策略
        |
适配器：模型网关 / 用户系统 / 业务数据 / 天气 / 向量检索
        |
基础设施：PostgreSQL / Redis / 向量库 / 对象存储 / 任务队列
        |
治理：日志、Trace、指标、评测、审计、CI/CD、告警
```

推荐新项目目录（C04/C05 等确认后再创建实现代码）：

```text
enterprise_agent/
  apps/api/                 # 对外 API 与流式协议
  apps/web/                 # 正式 Web（若批准）
  apps/admin/               # 知识与运营后台（后续）
  src/application/          # 用例与工作流
  src/domain/               # 领域模型和接口
  src/infrastructure/       # DB、模型、向量库、外部服务适配器
  src/observability/        # 日志、追踪、指标
  workers/                  # 知识导入、评测等异步任务
  evals/                    # 黄金问题集和回归阈值
  tests/                    # 单元、契约、集成、端到端测试
  deploy/                   # 容器与环境部署文件
  docs/                     # ADR、API、运维和用户说明
```
